# Source origin

This repository is the Project Zapp distribution. Its CDMA2000 software
stack comes from the open-source **1xBTS** project. This file records where
that code came from, what was not included, and what Project Zapp changed.

The files were copied from a checkout of that commit and are byte-identical
to it, except for the changes listed below.

**How the import was done:**
- The upstream Git history was not imported.
- There is no Git submodule, subtree or upstream remote.
- Nothing is cloned from 1xBTS at build or install time.

Project Zapp maintains this code independently from here on. There is no
ongoing synchronisation with 1xBTS.

## Layout

The upstream layout is kept at the repository root:
- `crates/` and `external/`: Rust crates and native wrappers;
- `proto/`: gRPC definitions;
- `config/`: node configuration;
- `1xbts-web/`: web dashboard;
- `apps/`, `sim/`, `docker/`, `test/`: supporting applications and tooling.

### Effect on functionality

**Voice codecs.** Without `csrc/`, `crates/cdma-voice` links a stub
(`crates/cdma-voice/zapp/codecs_unavailable.c`) that exports the same
functions, and every encoder and decoder constructor returns an error.
Everything else builds and runs. From reading the code, the expected effects
are as follows. None of this has been tested on a live network.

| Function | Expected behaviour without codecs |
| --- | --- |
| Mobile-to-mobile voice using the same service option | Unaffected: frames pass through without transcoding |
| Mobile-to-mobile voice across different codecs | Fails: no transcoder can be created |
| Ringback tones and custom ringtones (MSC) | Not played: the MSC logs a warning |
| WAV announcement playback (`voice.wav_file`) | Not played |
| Reverse-link silence frames generated by the BSC | Not generated: an error is returned |
| SIP voice gateway (`cdma-voice-gw`) | Call media cannot be set up |
| Uploading custom ringtones (pre-encoding in the HLR) | Rejected with an error |
| Software mobile station (`cdma-ms`) | Runs without voice encoding |

Restoring the original sources at `crates/cdma-voice/csrc/` re-enables the
reference codecs without code changes.

**Tests.** The tests that need excluded material do not run unless that
material is present. Nothing else about them changes:
- Tests that embed the material at compile time (`include_bytes!`) are
  compiled only when it is present.
- Tests that read it at run time are marked `#[ignore]` with a reason.
- Restoring the material re-enables them unchanged.

The cfg flags involved are:

| cfg flag | Set when this exists | Tests affected |
| --- | --- | --- |
| `zapp_reference_codecs` | `crates/cdma-voice/csrc/include/` | Codec tests in `cdma-voice`, plus codec-dependent tests in other crates (see below) |
| `zapp_evrc_b_vectors` | `crates/cdma-voice/tests/evrc_b_vectors/input.pcm` | EVRC-B/WB vector tests in `cdma-voice` |
| `zapp_prl_fixtures` | `crates/cdma-otasp/tests/fixtures/verizon_50408.prl` | PRL fixture tests in `cdma-otasp`, `cdma-hlr`, `cdma-msc`, `cdma-ms` and `csim` |
| `zapp_evdo_downlink_capture` | `test/iq/evdo_downlink_884490_4x_chip.wav` | Two EV-DO capture tests in `cdma-bts` |

No test assertion was changed or removed.

Two example files refer to excluded material:
- `sim/examples/card.yaml` refers to a PRL fixture, so it does not load until a
  PRL file is supplied at that path or the reference is changed.
- `config/msc.json` refers to `config/sample-sound.wav`. That file is
  included, but announcement playback needs the voice codecs.
